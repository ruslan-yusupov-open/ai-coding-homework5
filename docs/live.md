# Живой MCP: документация по HTTPS

Адрес: **https://mcp1.leadcm.com/mcp**. Транспорт — Streamable HTTP, ответы JSON,
без состояния сессий. Доступны `list_docs`, `search_docs`, `get_doc`.
Внутренние адреса, имена хостов и административные инструкции в публичный
репозиторий не включены.

## Подключение OpenCode

1. Получите отдельный MCP-ключ у владельца сервера по приватному каналу.
   Он не совпадает с ключом провайдера модели.
2. Установите `HOMEWORK5_MCP_TOKEN` в окружении запуска OpenCode. Чтобы не записывать
   ключ в историю PowerShell, используйте интерактивный скрытый ввод:

   ```powershell
   $mcpSecret = Read-Host 'MCP token' -AsSecureString
   $env:HOMEWORK5_MCP_TOKEN = [System.Net.NetworkCredential]::new('', $mcpSecret).Password
   opencode.cmd
   ```

3. Добавьте блок `mcp.homework5-live` из
   [примера конфигурации](../deploy/opencode.remote.json) в свой `opencode.json`.
   Запускайте OpenCode из того терминала, где задана переменная.
4. Проверьте `opencode.cmd mcp list`, затем отправьте:
   «Через MCP-сервер homework5-live вызови list_docs и перечисли документы».

Секрет передаётся только в `Authorization: Bearer ...`, не в URL или тексте запроса.
Авторизация — вручную выданный API-ключ с истечением срока, **не полный OAuth 2.1**:
`oauth: false` указан намеренно. Клиент должен поддерживать пользовательский заголовок.
В OpenCode этот вариант [официально поддерживается](https://opencode.ai/docs/mcp-servers/#disabling-oauth).
Для клиентов с обязательным браузерным OAuth понадобится отдельный OAuth-провайдер;
этот стенд не объявляет несуществующие OAuth endpoints.

## Граница доступа

- Клиент подключается по HTTPS. Прямой сетевой доступ к процессу MCP закрыт.
- Только точный маршрут `/mcp`; ключ проверяется до обработки HTTP-метода.
  Без ключа или с неверным/просроченным ключом — `401`.
- Случайный ключ содержит 48 случайных байт (384 бита), действует **30 дней**.
  Текущий срок: **13 октября 2026, 23:13:33 МСК**. Сервис хранит только SHA-256 ключа;
  исходный ключ лежит отдельно в root-only файле. Хеш сравнивается через `compare_digest`.
- Это один общий доступ только к документации. Раздельных пользователей и персональных
  квот нет; обладатели ключа имеют одинаковые права чтения и общие лимиты.
- Разрешены только Host `mcp1.leadcm.com` и Origin `https://mcp1.leadcm.com`
  либо отсутствие Origin для небраузерного клиента. Произвольный CORS не включён.
- Тело запроса — не более 16 КиБ, включая запросы без Content-Length.
  nginx ограничивает поток двумя запросами в секунду, допускает всплеск 10 запросов
  и не более четырёх одновременных обрабатываемых соединений. Превышение — `429`.
- Процесс работает от `homework5-docs` в отдельном `RootDirectory`, без shell,
  каталогов пользователей и SSH-ключей. Сеть изолирована; разрешены только Unix sockets.
  Веб-сервер передаёт соединения через отдельный socket с правами `root:www-data 0660`.
- Код и `knowledge` принадлежат root и доступны процессу только для чтения.
  Запись разрешена только в каталог журналов и ограниченный временный каталог.
  Лимиты — 256 МиБ RAM, половина одного CPU, 32 процесса/потока, 128 дескрипторов.
- Файловые ограничения исходного MCP сохраняются: Markdown в `knowledge`, запрет
  выхода через `..`, абсолютных путей, скрытых файлов, ссылок и junction, лимиты чтения.
- API-ключ не пишется в журналы приложения. Аргументы tools маскируются как в локальной
  версии; журнал ротируется по 1 МиБ с двумя резервными файлами. Запросы не должны
  содержать секретов: маскирование не является универсальным детектором.

Песочница использует ядро хоста и не является отдельной VM. Защита рассчитана
на ограниченный сервис документации, а не на исполнение произвольного кода.
Администратор хоста и администратор TLS-прокси остаются доверенными сторонами.

## Развёртывание и эксплуатация

Публикуются [шаблоны изоляции и проксирования](../deploy/README.md), без скриптов,
которые изменяют конфигурацию конкретной инфраструктуры. Код HTTP-сервера тот же,
что проверен на стенде; запуск локального stdio описан в основном README.

Ключи выдаёт, заменяет и отзывает администратор. Сервис получает через `MCP_AUTH_FILE`
путь к JSON с полями `sha256` и `expires_at`; исходный ключ не помещается в код.
Смена ключа требует обновления хеша и перезапуска процесса. Автоматического
бессрочного продления нет. Остановка службы и её socket прекращает доступ к MCP.

Зависимости экспортированы из `uv.lock` в
[requirements.txt](../deploy/requirements.txt) с хешами; для отдельного окружения:
`pip install --require-hashes -r deploy/requirements.txt`.

Проверки авторизации, размера тела и пяти MCP-вызовов через публичный URL:
[results.json](../validation/live/results.json).
Подключение официального SDK и реальная проверка лимита частоты:
[sdk-results.jsonl](../validation/live/sdk-results.jsonl).
Это проверки HTTP-клиентами; отдельная демонстрация агента в IDE сохранена
в [validation/ide](../validation/ide/README.md).

Реализация HTTP и авторизации: [http_server.py](../http_server.py).
Изоляция: [systemd service](../deploy/homework5-docs.service).
Проксирование и лимиты: [nginx location](../deploy/nginx-location.conf).
Локальные тесты: [test_http.py](../tests/test_http.py).
