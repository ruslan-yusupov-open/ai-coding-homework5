## Запрос 2

**Пользователь:**

Через MCP-сервер homework5-docs вызови search_docs с query="stdio". Объясни транспорт по найденным строкам.

**MCP:** `homework5-docs_search_docs`

```json
{
  "input": {
    "query": "stdio"
  },
  "result": {
    "status": "success",
    "call_id": "595e7955-08d6-47cf-83cf-b328ce937703",
    "data": {
      "matches": [
        {
          "path": "overview.md",
          "line": 16,
          "snippet": "Транспорт stdio: IDE запускает процесс и обменивается с ним сообщениями MCP."
        }
      ],
      "count": 1,
      "truncated": false
    },
    "error": null
  }
}
```

**Агент:**

Найдена одна строка — в `overview.md:16`.

Транспорт **stdio**: IDE запускает процесс-сервер и обменивается с ним сообщениями MCP напрямую через стандартные потоки ввода/вывода (stdin/stdout) этого процесса.

Ключевые черты такого транспорта:
- **Локальный** — процесс живёт на той же машине, что и IDE, сетевой канал не нужен.
- **IDE — клиент, MCP-сервер — запускемый процесс**: IDE сама стартует бинарь/скрипт сервера как дочерний процесс.
- **Обмен сообщениями** идёт через стандартные потоки: команды/запросы пишутся в `stdout` сервера (для клиента — `stdin`), ответы приходят обратно. Обычно по одному JSON-сообщению на строку (newline-delimited JSON-RPC).
- **Нет постоянного соединения** (в отличие от HTTP/SSE) — связь существует, пока жив дочерний процесс.

Если хочешь, могу прочитать весь `overview.md` через `get_doc` для более полного контекста.

## Запрос 3

**Пользователь:**

Через MCP-сервер homework5-docs вызови get_doc с path="security.md". Перечисли ограничения чтения.

**MCP:** `homework5-docs_get_doc`

```json
{
  "input": {
    "path": "security.md"
  },
  "result": {
    "status": "success",
    "call_id": "61a319d8-ee5b-4fbc-b815-7b2d49f793cf",
    "data": {
      "path": "security.md",
      "content": "# Безопасность\n\n## Граница доступа\n\nСервер читает только обычные файлы .md внутри папки knowledge рядом с server.py.\nАбсолютные пути, .., скрытые компоненты, символические ссылки и junction запрещены.\nКоманды оболочки не выполняются, файлы инструментами не изменяются.\nПапка knowledge предназначена для публичной документации: секреты туда не помещают.\n\n## Ограничения\n\nРазмер документа — максимум 128 КиБ. Не более 200 документов и 1000 элементов дерева.\nПоиск возвращает максимум 20 совпадений; один фрагмент — максимум 300 символов.\nЗапрос поиска — от 1 до 200 символов. Это буквальная подстрока, не регулярное выражение.\n\n## Логи\n\nКаждый вызов содержит call_id, имя инструмента, параметры и статус success/error.\nЛоги пишутся в stderr и logs/*.jsonl; stdout занят протоколом MCP.\nЗначения похожих на секреты строк в параметрах заменяются на [REDACTED].\n",
      "lines": 20
    },
    "error": null
  }
}
```

**Агент:**

Ограничения чтения (по `security.md`):

**Граница доступа**
- Читаются только обычные файлы `.md` внутри папки `knowledge` (рядом с `server.py`).
- Запрещены: абсолютные пути, `..`, скрытые компоненты, символические ссылки и junction.
- Не выполняются команды оболочки; файлы не изменяются инструментами.
- `knowledge` — для публичной документации, секреты туда не помещают.

**Размеры и лимиты**
- Документ — максимум **128 КиБ**.
- Не более **200 документов** и **1000 элементов дерева**.
- Поиск: максимум **20 совпадений**; один фрагмент — максимум **300 символов**.
- Запрос поиска: **1–200 символов**; это буквальная подстрока, не регулярное выражение.

**Логи** (связано с безопасностью)
- Каждый вызов логируется (`call_id`, инструмент, параметры, статус).
- Логи пишутся в `stderr` и `logs/*.jsonl` (stdout занят протоколом MCP).
- Строки, похожие на секреты, в параметрах заменяются на `[REDACTED]`.
