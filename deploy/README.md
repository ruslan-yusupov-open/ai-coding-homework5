# Примеры развёртывания HTTP-сервера

Основной способ повторить ДЗ — локальный stdio из корневого README.
В этом каталоге опубликованы шаблоны для самостоятельного HTTPS-развёртывания:

- `homework5-docs.service` и `.socket`: пример systemd-песочницы для Linux / Python 3.12.
- `nginx-location.conf`: маршрут `/mcp` с авторизацией в приложении и лимитами nginx.
- `opencode.remote.json`: подключение клиента с ключом из окружения.
- `requirements.txt`: зависимости с хешами, экспортированные из uv.lock.
- `check_live.py` и `check_sdk.py`: проверки заданного публичного endpoint.

Пути и пользователь в systemd-файлах — договорённости шаблона. Перед использованием
администратор создаёт пользователя, корень песочницы, venv, каталог журнала и файл
с хешем ключа, проверяет пути Python и файловые права. Шаблоны не содержат адресов
внутренней сети, SSH-настроек, действующих секретов или автоматического изменения
конфигурации существующих сайтов.

В контексте `http` nginx нужны зоны, используемые location:

```nginx
limit_req_zone $server_name zone=homework5_requests:1m rate=2r/s;
limit_conn_zone $server_name zone=homework5_connections:1m;
```

Маршрут включается только в нужный HTTPS virtual host. Если TLS завершает отдельный
прокси, администратор ограничивает доступ к origin доверенным прокси. Не публикуйте
origin по незащищённому HTTP. Замените домен в конфигурации nginx, `http_server.py`
и клиента при развёртывании на собственном адресе.

Скрипты проверок получают путь к приватному JSON через `MCP_TEST_ACCESS_FILE`.
Файл содержит `url`, `token`, `expires_at` и находится вне репозитория. Содержимое
ключа не выводится. `check_live.py --public` проверяет публичный HTTPS endpoint;
режим без флага рассчитан на локальный Unix socket из шаблона. `check_sdk.py`
дополнительно делает ограниченный всплеск из 20 запросов, чтобы проверить `429`.

Проверки структуры ключа и срока в приложении — не сервис выдачи OAuth-токенов.
Для этого примера ключ выдаёт администратор, клиент использует `oauth: false`.
